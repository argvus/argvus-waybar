`argvus-taskbar` ARGVUS টাস্কবার JSONC/CSS কনফিগারেশন এবং এর হেল্পার স্ক্রিপ্ট প্রদান করে। `argvus-waybar` Waybar বাইনারি প্রদান করে, আর `argvus-session` সার্ভিস শুরু করে এবং প্রযোজ্য ফাইল নির্বাচন করে। ব্যবস্থাপনা করা কপি এবং জেনারেট হওয়া কপি উভয়ই `argvus-config` দ্বারা লেখা হয়: এটি থিম লেয়ার প্রতিস্থাপন করে এবং টাস্কবার মার্জিন পুনরায় প্রয়োগ করে, `right-2` ইউটিলিটি-গ্রুপ মোড, বর্ডার রেডিয়াস এবং টেলিমেট্রি ফন্ট ব্লক যেকোনো থিম বা লেআউট অবস্থা পরিবর্তনের সময়। `argvus-appearance` আর এই ফাইলগুলি লিখে না; এটি কেবল পরিবর্তনটি কমিট করে এবং রিলোডের জন্য অনুরোধ করে।

## কনফিগারেশন প্রাধান্য

টাস্কবার এবং টেলিমেট্রি সারফেসের জন্য, `argvus sessionctl` এই ক্রমে স্বতন্ত্রভাবে কনফিগারেশন এবং স্টাইলশীট সমাধান করে:

```text
~/.config/argvus/data/generated/waybar/argvus-taskbar.{jsonc,css}
~/.config/argvus/data/generated/waybar/argvus-widget-telemetry.{jsonc,css}
        ↓
~/.config/argvus/data/waybar/argvus-taskbar.{jsonc,css}
~/.config/argvus/data/waybar/argvus-widget-telemetry.{jsonc,css}
        ↓
~/.config/waybar/argvus-taskbar.{jsonc,css}
~/.config/waybar/argvus-widget-telemetry.{jsonc,css}
        ↓
/usr/share/argvus/taskbar/config/argvus-taskbar.{jsonc,css}
```

যখন এটি সেট করা হয়, `$XDG_CONFIG_HOME` `~/.config` কে প্রতিস্থাপন করে। প্রথম বিদ্যমান ফাইল জয়ী হয়।

উত্পন্ন গাছটি **প্রথমে** আসে, তাই সক্রিয় থিম লেয়ার সবসময় জিতে যায়: একটি পুরানো ব্যবহারকারী বা নেটিভ কপি পূর্ববর্তী থিমে টাস্কবার রাখতে পারবে না। বাস্তব ফলাফল হল যে একটি নেটিভ `~/.config/waybar/` অর্ডার কেবল কার্যকর হয় যখন সংশ্লিষ্ট উত্পন্ন ফাইল অনুপস্থিত থাকে — উদাহরণস্বরূপ `rm -rf ~/.config/argvus/data/generated`-এর পরে এবং পরবর্তী রিলোডের আগে, বা যখন কোনো ফাইল কখনো প্রক্ষেপিত হয়নি। যদি আপনি এমন একটি স্থায়ী নেটিভ অর্ডার চান যা থিম পরিবর্তনের মধ্যেও টিকে থাকে, তাহলে উত্পন্ন গাছকে শুরু বিন্দু হিসেবে ব্যবহার করুন, অথবা স্বীকার করুন যে এই দুটি ফাইলের মালিকানা থিম লেয়ারের।

কনফিগারেশন মিশ্রিত করা হয়নি: একটি ওভাররাইড JSONC ফাইল সম্পূর্ণ টাস্কবার কনফিগারেশন প্রতিস্থাপন করে, এবং একটি ওভাররাইড CSS ফাইল সম্পূর্ণ স্টাইলশীট প্রতিস্থাপন করে।

প্যাকেজকৃত ডিফল্টগুলি শুধুমাত্র-পাঠযোগ্য ইনপুট। সম্পাদনা করবেন না:

```text
/usr/share/argvus/taskbar/config/argvus-taskbar.jsonc
/usr/share/argvus/taskbar/config/argvus-taskbar.css
```

## পরিচালিত ARGVUS কনফিগারেশন

সাধারণ ARGVUS সেশনগুলিতে ব্যবহৃত হয় নিম্নলিখিত পরিচালিত কপিগুলির অধীনে:

```text
~/.config/argvus/data/taskbar/argvus-taskbar.jsonc
~/.config/argvus/data/taskbar/argvus-taskbar.css
```

`argvus-config` একটি থিম প্রয়োগ করার সময় এই ফাইলগুলোকে প্যাকেজ করা ডিফল্ট থেকে পুনরায় তৈরি করে, তারপর ধ্রুবক ARGVUS অবস্থা যেমন টাস্কবার মার্জিন, `right-2` ইউটিলিটি-গ্রুপ মোড, বর্ডার রেডিয়াস এবং ফন্ট ব্লক পুনরায় প্রয়োগ করে। `data/waybar/argvus-taskbar.{jsonc,css}` এবং `data/waybar/argvus-widget-telemetry.{jsonc,css}` ক্ষেত্রেও একই ঘটনা ঘটে: তারা একটি চেহারা পরিবর্তনের সময় প্যাকেজ করা ডিফল্ট থেকে প্রতিস্থাপিত হয়, তাই সেখানে করা ম্যানুয়াল সম্পাদনাও হারিয়ে যায়।

`~/.config/argvus/data/generated/waybar/`-এর অধীনে তৈরি ফাইলগুলি উত্পন্ন অবস্থার এবং সরাসরি সম্পাদনা করা উচিত নয়; পুরো গাছটি পরবর্তী argvus config apply-এ `config.json` থেকে পুনর্নির্মিত হয়।  `argvus config apply` `argvus --setup --copy taskbar`-কে টাস্কবার কাস্টমাইজেশন পাথ হিসেবে ব্যবহার করবেন না; টাস্কবার রানার তার মূল `data/taskbar/` অবস্থানগুলি উপরে সমাধান করে।

## স্থায়ী JSONC কাস্টমাইজেশন

একটি টেকসই ম্যানুয়াল টাস্কবার কনফিগারেশনের জন্য, একটি সম্পূর্ণ নিজস্ব Waybar ওভাররাইড তৈরি করুন:

```sh
mkdir -p ~/.config/waybar
cp /usr/share/argvus/taskbar/config/argvus-taskbar.jsonc \
  ~/.config/waybar/argvus-taskbar.jsonc
```

`~/.config/waybar/`-এ কপি সম্পাদনা করুন। সাধারণ পরিবর্তনগুলির মধ্যে রয়েছে:

```jsonc
{
  "modules-left": ["hyprland/workspaces", "custom/my-module"],
  "custom/my-module": {
    "exec": "my-command",
    "interval": 10,
    "format": "{}"
  }
}
```

উদাহরণটি Waybar কাঠামো দেখায়; এটি কাস্টমাইজ করার সময় বাকী প্যাকেজকৃত কনফিগারেশনটি রাখুন। একটি স্থানীয় ওভাররাইড হলো একটি সম্পূর্ণ ফাইল, আংশিক JSONC ফ্র্যাগমেন্ট নয়। বিদ্যমান টাস্কবার ক্রিয়াগুলো কাজ করতে থাকার জন্য ARGVUS ডেস্কটপের প্রয়োজনীয় মডিউল এবং স্ক্রিপ্টগুলোর যত্ন নিন।

## স্থায়ী CSS কাস্টমাইজেশন

প্যাকেজ করা স্টাইলশীটটি তার রং সক্রিয় থিম বিল্ড থেকে আমদানি করে। যদি আপনি CSS অতিক্রম করেন, থিম ইমপোর্টটি বিল্ডের দিকে নির্দেশ করুন, যার পাথ থিম পরিবর্তনের সময় একই থাকে:

```sh
cp /usr/share/argvus/taskbar/config/argvus-taskbar.css \
  ~/.config/waybar/argvus-taskbar.css
sed -i '1s|.*|@import url("'"$HOME"'/.config/argvus/data/generated/theme/current/taskbar/theme.css");|' \
  ~/.config/waybar/argvus-taskbar.css
```

নেটিভ CSS এবং থিম ফাইলগুলি ব্যবহারকারীর মালিকানাধীন হয়ে যায়। থিম পরিবর্তনগুলি সেগুলি স্বয়ংক্রিয়ভাবে পুনর্নির্মাণ করবে না; ARGVUS থিম অ্যাসেট যোগ বা পরিবর্তন করলে সেগুলি সচেতনভাবে আপডেট করুন।

## পরিবর্তনগুলি প্রয়োগ করুন এবং কার্যকর ফাইলটি পরীক্ষা করুন

শুধুমাত্র টাস্কবার পুনরায় চালু করুন এর JSONC বা CSS পরিবর্তনের পরে:

```sh
argvus sessionctl restart waybar
```

সম্পূর্ণ সেশন/কনফিগারেশন রিফ্রেশের জন্য ব্যবহার করুন:

```sh
argvus sessionctl reload
```

চলমান Waybar প্রক্রিয়া কোন ফাইলগুলি প্রকৃতপক্ষে ব্যবহার করছে তা দেখতে:

```sh
pgrep -af 'waybar.*argvus-taskbar'
```

প্রক্রিয়াটি কার্যকর JSONC ফাইলের জন্য `-c` এবং কার্যকর CSS ফাইলের জন্য `-s` দেখানো উচিত। যদি একটি নেটিভ ফাইল থাকে, তবে ম্যানেজ করা ARGVUS কপিতে পরিবর্তন করা সক্রিয় টাস্কবার পরিবর্তন করবে না যতক্ষণ না নেটিভ ফাইলটি সরানো বা আপডেট করা হয়।

সার্ভিস এবং লগগুলি নিম্নলিখিতভাবে পরীক্ষা করা যেতে পারে:

```sh
systemctl --user status argvus-taskbar.service
journalctl --user -u argvus-taskbar.service -n 50 --no-pager
```

ব্যবহারকারী-সামনের ফিচারগুলোর জন্য [টাস্কবার](/docs/argvus-taskbar/taskbar/) দেখুন এবং ইনস্টল করা ও ব্যবহারকারীর পাথের জন্য [ফাইল অবস্থান](/docs/reference/file-locations/) দেখুন।

## হাইপ্রল্যান্ড কাজের স্থান সামঞ্জস্যতা

ARGVUS বিল্ডে উভয়ই পুরানো সংখ্যার ওয়ার্কস্পেস আইডি এবং Hyprland 0.57 টেক্সট-মূলক ওয়ার্কস্পেস ঠিকানা গ্রহণ করে। `id` ছাড়া নামকৃত ওয়ার্কস্পেসগুলো প্রক্রিয়া-স্থানীয় অভ্যন্তরীণ পরিচয়কারক ক্রমাগতভাবে ওয়ার্কস্পেস স্ন্যাপশট, ক্লায়েন্ট, মনিটর এবং ইভেন্ট জুড়ে পায়। এই পরিচয়কারকগুলো কখনও Hyprland-এ পাঠানো হয় না: ওয়ার্কস্পেস বোতামগুলো আসল নাম প্রেরণ করে।

`hyprland/workspaces.workspace-metadata` ঐচ্ছিকভাবে একটি JSON ফাইলের নাম দেয় যা `$XDG_RUNTIME_DIR` এর সাথে সম্পর্কিত, যেমন `argvus/project-workspaces.json`। প্রতিটি ওয়ার্কস্পেস নাম একটি অবজেক্টের সাথে মানচিত্রিত হয় যার মধ্যে `label` এবং `tooltip` স্ট্রিং থাকে। লেবেলগুলি Pango পাঠ হিসেবে এস্কেপ করা হয় এবং মিল বা ক্লিক লক্ষ্য পরিবর্তন করে না। অনুপস্থিত মেটাডেটা স্থানীয় ওয়ার্কস্পেস নেমে ফিরে যায়। `argvus projects` উৎপন্ন প্রকল্প মেটাডেটার মালিক; তালিকা/ভাষার পরিবর্তনের পরে প্রকল্পটি পুনরায় খুলুন এটি রিফ্রেশ করতে।


## উইন্ডো বোতাম এবং অ্যাপ্লিকেশন বার

প্রতিটি মনিটরে একটি দ্বিতীয় ওয়েবার প্রদর্শিত হয়, প্রধান টাস্কবারের বিপরীত প্রান্তে। এটি শুধুমাত্র সেই মনিটরের বর্তমান ওয়ার্কস্পেসের সমস্ত উইন্ডো তালিকাভুক্ত করে, সেই ওয়ার্কস্পেসের ন্যূনতম করা উইন্ডোগুলিও সহ। একটি খোলা বিশেষ ওয়ার্কস্পেস অগ্রাধিকার পায়। পিন করা উইন্ডোগুলি দৃশ্যমান থাকে; লুকানো গ্রুপ ট্যাব অতিরিক্ত এন্ট্রি তৈরি করে না, এবং একটি ন্যূনতম গ্রুপের একটি পুনরুদ্ধার এন্ট্রি থাকে। একটি অ্যাপ্লিকেশনের ভিতরের ট্যাবগুলি আলাদাভাবে গণনা করা হয় না। ন্যূনতম করা এন্ট্রিগুলি তাদের মূল মনিটর/ওয়ার্কস্পেস সম্পর্কটি ধরে রাখে। একটি নিষ্ক্রিয় উইন্ডোতে ক্লিক করুন এটি সক্রিয় করতে, একটি সক্রিয় উইন্ডোতে ক্লিক করুন এটি ন্যূনতম করতে, অথবা একটি ন্যূনতম উইন্ডোতে ক্লিক করুন এটি পুনরুদ্ধার করতে; এর প্রসঙ্গ মেনু পুনরুদ্ধার, ন্যূনতম, সর্বাধিক/পুনরুদ্ধার এবং বন্ধের অপশন দেয়। অজানা অ্যাপ্লিকেশন আইকনগুলি একটি উইন্ডো চিহ্নে ফিরে আসে।

`hyprland/argvus-windows` মডিউলটি `argvus windows watch --json` থেকে একটি JSON স্ট্রিম গ্রহণ করে। GTK আপডেটগুলি মূল থ্রেডে চলে; অ্যাকশনগুলি আর্গুমেন্ট অ্যারের এবং যাচাই করা উইন্ডো ঠিকানাগুলি ব্যবহার করে। পুনরুদ্ধারের প্রস্তুতি কম্পোজিটার লেয়ার তালিকার বিরুদ্ধে নিশ্চিত করা হয়।
