---
title: Переопределения Waybar и панели задач
description: Настройте панель задач ARGVUS Waybar без редактирования упакованных файлов.
---
`argvus-taskbar` предоставляет конфигурацию панели задач ARGVUS в формате JSONC/CSS и вспомогательные скрипты. `argvus-waybar` предоставляет бинарный файл Waybar, в то время как `argvus-session` запускает сервис и выбирает актуальные файлы. Управляемая копия и сгенерированная копия обе создаются `argvus-config`: он заменяет слой темы и повторно применяет отступы панели задач, режим утилиты `right-2`, радиус границы и блок шрифта телеметрии каждый раз, когда меняются темы или состояние макета. `argvus-appearance` больше не записывает эти файлы; он только фиксирует изменения и запрашивает перезагрузку.

## Приоритет конфигурации

Для панели задач и поверхности телеметрии `argvus sessionctl` решает вопросы конфигурации и таблицы стилей независимо в следующем порядке:

```text
~/.config/argvus/data/generated/waybar/argvus-taskbar.{jsonc,css}
~/.config/argvus/data/generated/waybar/argvus-widget-telemetry.{jsonc,css}
        ↓
~/.config/argvus/data/waybar/argvus-taskbar.{jsonc,css}
~/.config/argvus/data/waybar/argvus-widget-telemetry.{jsonc,css}
        ↓
~/.config/waybar/argvus-taskbar.{jsonc,css}
~/.config/waybar/argvus-widget-telemetry.{jsonc,css}
        ↓
/usr/share/argvus/taskbar/config/argvus-taskbar.{jsonc,css}
```
`$XDG_CONFIG_HOME` заменяет `~/.config`, когда он установлен. Побеждает первый существующий файл.

Сгенерированное дерево идет **первым**, поэтому активный слой темы всегда побеждает: устаревшая пользовательская или нативная копия не должна сохранять панель задач на предыдущей теме. Практическое следствие заключается в том, что нативное переопределение `~/.config/waybar/` вступает в силу только при отсутствии соответствующего сгенерированного файла — например, после `rm -rf ~/.config/argvus/data/generated` до следующей перезагрузки, или когда файл никогда не был спроектирован. Если вы хотите создать долговременное нативное переопределение, которое сохраняется при смене темы, используйте сгенерированное дерево в качестве отправной точки или примите, что слой темы управляет этими двумя файлами.

Конфигурация не объединяется: файл JSONC с переопределением заменяет полную конфигурацию панели задач, а файл CSS с переопределением заменяет полную таблицу стилей.

Упакованные значения по умолчанию являются только для чтения. Не редактируйте их:

```text
/usr/share/argvus/taskbar/config/argvus-taskbar.jsonc
/usr/share/argvus/taskbar/config/argvus-taskbar.css
```
## Управляемая конфигурация ARGVUS

Обычная сессия ARGVUS использует управляемые копии в следующем месте:

```text
~/.config/argvus/data/taskbar/argvus-taskbar.jsonc
~/.config/argvus/data/taskbar/argvus-taskbar.css
```
`argvus-config` воссоздает эти файлы из стандартных настроек при применении темы, затем повторно применяет постоянное состояние ARGVUS, такое как отступы панели задач, режим группы утилит `right-2`, радиус границы и блок шрифта. То же самое относится к `data/waybar/argvus-taskbar.{jsonc,css}` и `data/waybar/argvus-widget-telemetry.{jsonc,css}`: они заменяются на стандартные настройки при изменении внешнего вида, поэтому ручные правки там также теряются.

Сгенерированные файлы под `~/.config/argvus/data/generated/waybar/` являются производным состоянием и не должны редактироваться напрямую; всё дерево будет восстановлено из `config.json` при следующем `argvus config apply`. Не используйте `argvus --setup --copy taskbar` в качестве пути настройки панели задач; исполнитель панели задач определяет её канонические местоположения `data/taskbar/` выше.

## Постоянная JSONC настройка

Для долговременной ручной конфигурации панели задач создайте полный нативный оверрайд Waybar:

```sh
mkdir -p ~/.config/waybar
cp /usr/share/argvus/taskbar/config/argvus-taskbar.jsonc \
  ~/.config/waybar/argvus-taskbar.jsonc
```
Отредактируйте текст в `~/.config/waybar/`. Распространенные изменения включают:

```jsonc
{
  "modules-left": ["hyprland/workspaces", "custom/my-module"],
  "custom/my-module": {
    "exec": "my-command",
    "interval": 10,
    "format": "{}"
  }
}
```
Пример иллюстрирует структуру Waybar; при настройке сохраняйте остальную часть пакета конфигурации. Родное переопределение — это полный файл, а не частичный фрагмент JSONC. Сохраняйте модули и скрипты, необходимые рабочему столу ARGVUS, если вы хотите, чтобы существующие действия на панели задач продолжали работать.

## Постоянная настройка CSS

Упакованная таблица стилей импортирует свои цвета из активной сборки темы. Если вы переопределяете CSS, указывайте импорт темы на сборку, путь к которой остается одинаковым при смене темы:

```sh
cp /usr/share/argvus/taskbar/config/argvus-taskbar.css \
  ~/.config/waybar/argvus-taskbar.css
sed -i '1s|.*|@import url("'"$HOME"'/.config/argvus/data/generated/theme/current/taskbar/theme.css");|' \
  ~/.config/waybar/argvus-taskbar.css
```
Файлы Native CSS и темы становятся собственностью пользователя. Изменения темы не будут автоматически их пересоздавать; обновляйте их сознательно, когда ARGVUS добавляет или изменяет ресурсы темы.

## Применение изменений и проверка эффективного файла

Перезапускайте только панель задач после изменения её JSONC или CSS:

```sh
argvus sessionctl restart waybar
```
Для полного обновления сеанса/конфигурации используйте:

```sh
argvus sessionctl reload
```
Чтобы увидеть, какие файлы фактически использует запущенный процесс Waybar:

```sh
pgrep -af 'waybar.*argvus-taskbar'
```
Процесс должен показывать `-c` для действительного файла JSONC и `-s` для действительного файла CSS. Если существует нативный файл, изменения в управляемой копии ARGVUS не повлияют на активную панель задач до тех пор, пока нативный файл не будет удален или обновлен.

Сервис и журналы можно проверить с помощью:

```sh
systemctl --user status argvus-taskbar.service
journalctl --user -u argvus-taskbar.service -n 50 --no-pager
```
Смотрите [Taskbar](/docs/argvus-taskbar/taskbar/) для функций, доступных пользователю, и [file locations](/docs/reference/file-locations/) для установленных и пользовательских путей.

## Совместимость рабочего пространства Hyprland

Сборка ARGVUS принимает как устаревшие числовые идентификаторы рабочих пространств, так и текстовые адреса рабочих пространств Hyprland 0.57. Именованные рабочие пространства без `id` получают локальные для процесса внутренние идентификаторы последовательно в пределах снимков рабочего пространства, клиентов, мониторов и событий. Эти идентификаторы никогда не отправляются в Hyprland: кнопки рабочего пространства передают реальное имя.

`hyprland/workspaces.workspace-metadata` при желании указывает имя JSON-файла относительно `$XDG_RUNTIME_DIR`, например, `argvus/project-workspaces.json`. Каждое имя рабочей области отображается на объект с строками `label` и `tooltip`. Метки экранируются как текст Pango и не изменяют соответствие или цели щелчка. Отсутствующие метаданные заменяются на имена рабочих областей по умолчанию. `argvus projects` управляет производными метаданными проекта; повторно откройте проект после изменений списка/языка, чтобы обновить их.

## Кнопки окна и панель приложения

Второй Waybar появляется на каждом мониторе, на противоположной стороне от основной панели задач. Он отображает только окна, принадлежащие текущему рабочему пространству этого монитора, включая свернутые окна этого рабочего пространства. Открытое специальное рабочее пространство имеет приоритет. Закрепленные окна остаются видимыми; скрытые вкладки группы не создают дополнительных записей, а у свернутой группы есть одна запись для восстановления. Вкладки внутри приложения не перечисляются отдельно. Свернутые записи сохраняют свою исходную привязку к монитору/рабочему пространству. Нажмите на неактивное окно, чтобы активировать его, на активное окно — чтобы свернуть, или на свернутое окно — чтобы восстановить; его контекстное меню предлагает восстановить, свернуть, развернуть/восстановить и закрыть. Значки неизвестных приложений заменяются символом окна.

Модуль `hyprland/argvus-windows` потребляет поток JSON из `argvus windows watch --json`. Обновления GTK выполняются в главном потоке; действия используют массивы аргументов и проверенные адреса окон. Готовность к восстановлению подтверждается по списку слоев композитора.
